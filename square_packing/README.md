# 图 → 方块填充（矩形对偶）／圆盘填充（相切圆）

把一张平面三角剖分图变成**方块填充**：每个顶点一个方块，图上相邻 ⟺ 方块**接触**
（共享一段正长度的边），4 个角点落在大长方形的四个角上。第四幅图是同一张图上的
**圆盘填充**：每个顶点一颗圆，图上相邻 ⟺ 两圆相切，四个角各 90°。

外边界可以是 4 个点（8 个预设）、k > 4 个点（两张手写真实地图：美国各州 / 中国各省），
**也可以是你自己的图** —— 按 `u` 或点「导入图…」，选文件 / 拖进来 / 粘贴都行。

```
图（Tutte 嵌入：边界点钉在凸四边形上 —— 4 个角点占 4 个角，其余沿边均匀铺开）
  → 离散 Ricci 流（目标曲率：角点 π/2、其余 0）→ 平直度量
  → 等距铺展 → 长方形（长宽比 = 共形模）
  → REL（每条内边蓝 = 下→上 / 红 = 左→右）→ 矩形对偶（并查集 + 最长路）→ 方块填充
同一份输入、同一套目标曲率，只换度量族（相切度量 l_ij = r_i + r_j）：
  → 同一个 develop → 圆心 → 相切圆盘填充（四角 90°）
```

![四幅图界面：① 输入图 ② 平直铺展 ③ 方块填充 ④ 圆盘填充](images/application.png)

*界面全貌（`W₅`，`npm run dev` 的样子）：左栏选图 / 视图 / 长宽比 / 输入四边形 / 显示，
中间四幅图**同步高亮同一个顶点**，右栏把每一步的数字都摆出来。*

## 怎么跑

```bash
npm install
npm run dev      # http://localhost:5175
npm run check    # 无界面自检：601 项断言全绿，每项都打数字
npm run build    # 产物在 dist/
```

核心算法在 `src/core/`，**零依赖**的纯 ESM，`node` 里可以直接 `import`
（`npm run check` 就是这么跑的：不开浏览器、不碰 DOM）。上手四步：

1. 打开 `http://localhost:5175`，鼠标悬停任意顶点 —— 四幅图里同一个顶点一起亮。
2. 拖**「输入四边形」**（正方形 → 斜四边形）：② 的四角被流掰回直角、① 的内点跟着动。
   拖**「长宽比」**：只把 ③ 在 x 方向整体拉伸。**两个滑杆都不影响 ④**（度量里没有坐标）。
3. 按 `9` / `0` 看两张**真实地图**：① 按经纬度画，灰虚线块 = 人工块、橙虚线 = 人工补的边。
4. 按 `u` 导入自己的图，按 `?` 看全部快捷键（含侧栏全部开关）。

## 界面

四幅图同步高亮同一个顶点 —— 这是理解整套流程的关键：

| | 是什么 |
| --- | --- |
| **① 输入图** | Tutte 嵌入（角点钉在输入四边形上），蓝/红 = REL 的颜色与方向；地图改按**经纬度**画（只用于显示） |
| **② 平直铺展** | Ricci 流之后的实长度铺展：边界已经成直线、四角已经成直角 |
| **③ 方块填充** | 矩形对偶铺满大长方形（地图上给每个方块标州名/省名） |
| **④ 圆盘填充** | 同一张图上的相切圆盘（换度量族，目标曲率与 ③ 相同，与 ①②③ 并行算出来） |

## 导入自己的图（按 `u`）

文件会变成和内建预设**同一个形状的 preset**，所以四个视图组件一行都不用改。
**边表**（首字符不是 `{`）：

```
# 每行一条「u v」；# 开头的注释与空行都跳过；可选表头 `n m`（m 对不上就当成一条边读）
# corners: 0 3 7 4    ← 可选：外圈上逆时针的 4 个角点 S E N W
# boundary: 0 1 2 3   ← 可选：外圈（一般平面图必须给；三角剖分不用）
# pos: 0.1 0.2        ← 可选：顶点坐标（**只用来画 ①**）
0 1
```

**JSON**（首字符 `{`）：`nv` + `faces`（或 `edges`，两个都给时 `edges` 优先），
可选 `corners` / `pos` / `names`；`faces` 只放**三角形内面**，朝向写乱不要紧
（先按「相邻面反着走公共边」传播一致）。下标基：0 基为默认，出现等于 nv 的下标
（或表头里的 n）就按 1 基读（PACE `.gr` 惯例），界面会说明用了哪个基。

```json
{ "name": "hex7", "nv": 7, "faces": [[0,1,6],[1,2,6],[2,3,6],[3,4,6],[4,5,6],[5,0,6]],
  "corners": {"S":4,"E":0,"N":2,"W":3}, "names": ["东","东北","西北"] }
```

**面和外圈从哪来**：给了 `faces` 就用；声明了 `# boundary:` 就走「嵌入 + 面游走 +
三角化」；什么都不声明就走 **3-团法**（`面 = 3-团`、`外圈 = 只属于一个 3-团的边`，
10 张内建图上逐条验过它等于 `mesh.boundary`）。

**不够格的地方自动修补并逐条记账，修不掉的明确拒绝**：

| 偏离 | 处理 |
| --- | --- |
| 面是 ≥ 4 边形但是个团 | 加对角线剖成三角形 |
| 面是 ≥ 4 边形又不是团 | 插一个**人工点**星形剖开（界面上是灰块） |
| 内点度 < 4 / 外圈上多余的度 2 点 | **并入**一个邻居（不丢任何相邻） |
| 分离三角形（**贴着外圈**的那种也认得出） | 翻掉它的一条边 |
| 球面三角剖分（χ = 2） | 沿一个度 4 的顶点**剪开**成盘 |
| K₅ / K₃,₃、不连通、外圈只有 3 个点、闭合曲面却没有度 4 的顶点、自环、重复边 | **拒绝**，说清卡在哪一条 |

**4 个角点**：声明了就用；否则自动选 —— 外圈上度为 2 的点强制当角点，剩下的名额按
「最大化最小间隔」贪心补满，选完再**干跑**一遍（最多 6 组候选 × 正 / 反朝向，抛了就换
下一组），实测「角点选得不好」是真会抛。自动选角只保证能跑通 + 间隔均匀，**不保证和你
想的那组一样**：外圈 k > 4 时长宽比取决于哪 4 个点当角点（中国地图上所有可行角点组给
`0.681406` … `0.902062`，相差 32.4%），要控制就得自己声明。文件里的坐标只用来画 ①。

## 算法（五步）

**前提**：每个内面是三角形、外边界被 4 个角点分成 4 段非空链、无分离三角形、内点度 ≥ 4
（合称 PTP）—— 这是矩形对偶存在的**充要条件**（Kozminski–Kinnen）。

1. **初始嵌入**（`embed.js`）：外边界钉在输入四边形上（k > 4 时 4 个角点钉四角、其余沿边
   均匀铺开），内部点解 Tutte 线性系统，再用**均值坐标（MVC）**细化 3 轮（权重全正 ⟹
   3-连通图无翻转）。产出的是 Ricci 流的**背景度量 l̄**。
2. **离散 Ricci 流**（`ricci.js`）：`l_ij = l̄_ij · e^((u_i+u_j)/2)`，曲率 `K = 2π − Σθ`
   （内点）/ `π − Σθ`（边界点），目标 `K̄ = π/2`（4 个角点）、`0`（其余）。Gauss–Bonnet
   自动给 `ΣK = 2π`。带阻尼 Newton：`dK = −½ L du`（`L` = 余切 Laplacian，半正定），每步
   解 `L du = −2(K − K̄)`（钉一个自由度定整体缩放），回溯线搜索保证 `max|K − K̄|` 下降。
   小图上 4…5 步到 `1e-15`；**大图上会停住**（离散共形类的数学障碍，不是 bug）——
   这时长宽比改用同四边形上的参考值兜底，并在界面上如实标出来。
3. **等距铺展**（`unfold.js`）：按边长逐个三角形摊平。收敛后角点累计角 = π/2 ⟹ 拐直角、
   墙点 = π ⟹ 直线穿过，所以铺出来正好是**矩形**（边界直线偏差 `0.000e+0`、四角直角偏差
   `4.4e-16`、对边等长残差 `4.4e-16`）。`W/H` 是**离散共形模**，只由输入四边形决定
   （k = 4 时与图的内部结构无关）。
4. **REL**（`rel.js`）：每条内边带颜色和方向 —— `blue (u,v)` = R(u) 在 R(v) **下面**（定 y），
   `red (u,v)` = R(u) 在 R(v) **左边**（定 x）。约束是每个顶点绕序的四块（出蓝 → 出红 →
   入蓝 → 入红）都非空，边界点贴着哪面墙就缺哪一块，外边由几何定死。带重启的回溯搜索。
5. **矩形对偶 + 校验**（`rectdual.js` / `verify.js`）：把 REL 当**等式**（`red: x2(u) = x1(v)`
   等），union-find 合并成「层」，每个顶点加 `x1 → x2`、`y1 → y2` 的 DAG 边，层坐标 =
   **最长路**（取最小整数解；各段宽度本来自由）；最后按长宽比把 x 整体缩放。校验不靠
   「看起来像」：面积和 = `W·H`、接触 ⟺ 图上有边（缺边 / 多边都数）、无十字点、无自捏。

**第四幅图只换第 2 步的度量族**：相切度量 `l_ij = r_i + r_j`（`u_i = log r_i`），目标曲率
一模一样，第 3 步的 `develop(mesh)` 原样就是解码器（不需要 REL）。解出来四角各 90°、
墙点各 180°、内点各 360°，于是 4 条墙的圆心链围成一个矩形（k = 4 时必是正方形，可证）。
同一张图还能换一种边界条件（极大填充：所有边界圆共一个外圆，Koebe–Andreev–Thurston），
代价是四角不再 90°，代码里是 `mode:'maximal'`，不在界面上。

## 约定与已知限制

- **角点**：铺展后按坐标认左下 `S`、右下 `E`、右上 `N`、左上 `W`（不是按输入编号）。
  **长宽比** `W/H`：`W` = S→E 方向的边长，正方形输入时为 1。
- **REL 颜色**：蓝 = 上下相邻（`u` 的下方是 `v`），红 = 左右相邻（`u` 在 `v` 左边），
  箭头按 `from → to` 画；外边钉死（SW/NE 蓝、SE/WN 红）。
- **为什么是矩形而不是正方形**：一般图上等大方块填充根本不存在，能保证的只有**矩形对偶**
  （矩形可大小不等，允许 T 型接头）。
- 输入必须是 **PTP**；不满足时矩形对偶可能不存在，界面会报哪一条不满足（导入的图是例外：
  偏离的地方自动修补并逐条列出理由，修不掉的明确拒绝）。
- **导入的一般平面图必须声明外圈**（`# boundary:` 或 JSON 的 `faces`）—— 边表里没有
  「哪个面是外面」这条信息，猜不出来。
- **外圈 k > 4 时长宽比取决于角点选择**；k = 4 时角点没得选，长宽比只由输入四边形决定。
- 铺展图可能自交叠 —— 不影响组合信息（REL 只用旋转序和层间距），只影响 ② 好不好看。
- **圆盘填充的边界圆可以小到亚像素**（美国那张边界半径比 1.24e4）：这是「相切 + 边界点
  占多数」的固有后果。界面照实画 + 标数字，不给小圆放大或设最小尺寸。
- 两张地图的数据是**手写**的（环境无网络），真实相邻关系有 14 处（美国）/ 8 处（中国）
  公开偏离；经纬度只用于显示，不过问结构。

## 文件结构

```
src/core/         纯 ESM、无 DOM 依赖，Node 里可直接跑
  presets.js      8 个预设 + 随机 PTP 生成器 ｜ ptp.js  PTP 校验
  embed.js        Tutte / MVC 嵌入 + 平面性检查 ｜ mesh.js  半边邻接、曲率、Laplacian
  ricci.js        离散 Ricci/Yamabe 流（Newton + 回溯线搜索）
  unfold.js       逐三角形等距铺展、矩形残差 ｜ rel.js  REL 的 CSP + 公理校验
  rectdual.js     REL → 矩形（并查集 + 最长路）｜ verify.js  铺满校验
  circlepack.js   圆盘填充 ｜ modulus.js  共形模参考 ｜ pipeline.js  串起全流程
  graphfile.js    导入策略（解析 + 修补 + 抢角）｜ examples.js  三个内联示例
  diskbuild.js + mapgraph.js + maps/{us,cn,index}.js   两张手写地图 → 平面三角剖分
src/components/   Panel / GraphView / FlatView / PackingView / CirclePackingView / Stats
                  / Help / ImportPanel ｜ src/App.jsx  界面状态与四视图编排
scripts/check.mjs 无界面自检（601 项，每项都打数字；--faces 打印地图的面列表）
```
